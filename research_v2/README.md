# PromptShield Research V2

This directory contains the **research layer** used to turn the original course PoC into a more defensible empirical study for graduate admissions.

The original application in the repository root is intentionally left unchanged.

## Research question

> **Does prompt-injection detection performance reliably predict downstream security outcomes?**

Supporting questions:
1. Does attack obfuscation reduce detector performance?
2. Can adaptive attacks evade detection while preserving the original adversarial objective?
3. When detection fails, does the victim actually leak protected information?

## What has been added

### `prompt_conditions.py`
Defines two detector conditions:

- `baseline`
- `structured`

The structured condition is a security-analysis checklist. It is deliberately **not** described as hidden chain-of-thought.

### `canary_victim.py`
Defines synthetic enterprise scenarios using exact canary secrets. This makes leakage scoring deterministic.

### `metrics.py`
Implements:
- Precision / Recall / F1
- False Positive Rate
- False Negative Rate
- category-level metrics
- Evasion Rate
- Objective-Preservation Rate
- Leakage Rate
- True Attack Success Rate
- Detection × Leakage matrix

### `../data/research_v2/benchmark_v2.json`
A fixed 60-case benchmark:
- 20 benign
- 20 direct attacks
- 20 covert/contextual attacks

Every case records category, scenario, objective, protected target, and provenance.

### `../data/research_v2/adaptive_seeds.json`
12 fixed malicious seed objectives for adaptive-attack experiments.

## Evidence rule

Do **not** put Research V2 numerical findings into admissions material until the experiments have actually been run and raw results are saved.

The existing course results may be described only as **preliminary PoC evidence**.

## Next implementation step

The remaining code to add is an executable experiment runner that:

1. calls the existing NVIDIA NIM detector with the two research prompt conditions;
2. calls a synthetic canary victim;
3. records raw outputs without silently converting parse failures to benign predictions;
4. runs the 60-case benchmark with repeated trials;
5. runs adaptive seeds and logs objective-preservation + leakage outcomes;
6. writes machine-readable outputs to `results/research_v2/`.

Because those experiments require the repository owner's API keys, the code can be prepared here, but the final numerical results should be generated by running the scripts in the owner's environment.
